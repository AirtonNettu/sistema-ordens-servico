# Visão do Projeto

**Projeto:** Sistema de Ordens de Serviço para Assistência Técnica  
**Status:** descoberta inicial — conteúdo não validado  
**Finalidade:** projeto-laboratório para praticar Engenharia de Software de ponta a ponta.

## Contexto conhecido
O domínio escolhido é o gerenciamento de ordens de serviço de uma assistência técnica. Ainda não foi entrevistado um responsável pelo negócio; fluxos e dificuldades operacionais são desconhecidos.

## Problema a resolver
**Pendente:** registrar, com as palavras do stakeholder, como funciona o atendimento atual e quais problemas justificam o sistema.

## Objetivo de negócio
**Pendente:** definir resultado desejado e critério de sucesso.

## Stakeholders e usuários
**A identificar na entrevista.** Papéis possíveis (cliente, atendente, técnico, gestor) são hipóteses, não escopo aprovado.

## Limites do projeto (escopo)
- Incluído: **a definir**.
- Não incluído: **a definir**.
- MVP: **a definir após levantamento**.

## Questões em aberto
1. Como uma OS nasce, muda de estado e é encerrada hoje?
2. Quem participa do atendimento e que informações cada pessoa precisa?
3. Qual o problema operacional mais custoso ou frequente?
4. Como saberemos que o sistema resolveu o problema?

## Critério para aprovação
Visão validada pelo stakeholder antes da definição da arquitetura ou implementação.
